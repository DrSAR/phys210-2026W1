String formatting (3 styles)¶

Percent-style (%) string formatting (old style)

print("The answer is %6.4f +/- %8.3f" % (y, dy) )

str.format() (new style)

print("The answer is {:6.4f} +/- {:8.3f}".format(y, dy))

f-strings

print(f"The answer is {y:6.4f} +/- {dy:8.3f}")

1. What do the numbers mean here?

print(f"The answer is {y:6.4f} +/- {dy:8.3f}")

2. {tau:.3f} versus {tau:.3}    3. negative slicing, my_string[-6:-3]

The n in {dy:n.3f} is the minimum field width

  • Specifies minimum number of characters to display a value.
  • If the actual value has fewer the field will be padded with spaces to meet minimum width.
  • If the actual value has more characters, minimum field width is ignored and the full value is displayed.
  • n does not have to be specified, e.g., {dy:.3f}

Reading a format specifier: {value:width.precision f}¶

{y:6.4f} has three parts after the colon:

  • width (6) - the minimum number of characters reserved for the whole number
  • precision (.4) - how many digits are shown after the decimal point
  • f - fixed-point notation (never scientific)

Padding spaces are added on the left until the value reaches the width. If the value already needs more characters, the width is ignored and nothing is cut.

In [3]:
dy = 12.3456
y  = 12345.6789

print(f"[{dy:8.3f}]")   # 6 chars in an 8-wide field -> padded
print(f"[{y:6.4f}]")    # 10 chars in 6-wide field -> width ignored
print(f"[{dy:.3f}]")    # no width -> no padding

[  12.346]
[12345.6789]
[12.346]

Which type code? The five you will actually use¶

code meaning example output
d integer, base 10 f"{42:d}" 42
f fixed point f"{v:.2f}" 1234.57
e scientific f"{v:.3e}" 1.235e+03
g general: e or f, whichever reads better f"{v:.3g}" 1.23e+03
s string f"{name:s}" Rainy days

A literal % in an f-string is just % — no escaping needed.

In [7]:
# the five type codes, on one value
v = 1234.5678
print(f"d  {42:d}")
print(f"f  {v:.2f}")
print(f"e  {v:.3e}")
print(f"g  {0.00001234:.3g}   {v:.3g}")
print(f"s  {'Rainy days':s}")

f  1234.57
e  1.235e+03
g  1.23e-05   1.23e+03
s  Rainy days

Reference: the %-style conversion table¶

Only for the old "..." % (...) style — this is the table in the python-course.eu reading.

code meaning code meaning
d signed integer decimal i signed integer decimal (same as d)
o unsigned octal u obsolete, equivalent to d
x unsigned hex, lower case X unsigned hex, upper case
e float, exponential, lower e E float, exponential, upper E
f float, decimal F float, decimal
g e if exponent > -4 or < precision, else f G same, but upper case
c single character r string via repr()
s string via str() % a literal % character

The f-string table is not the same table¶

Three rows above do not transfer (all three raise ValueError):

%-style in an f-string / .format()
%i, %u invalid — f"{7:i}" → ValueError; there is only d
%r not a type code — use f"{s!r}", before the colon

And the f-string spec has codes that %-style does not:

code meaning example
b binary f"{10:b}" → 1010
n locale-aware number f"{1234567:n}"
% multiply by 100, append % f"{0.25:.1%}" → 25.0%

Alignment, fill and thousands separators¶

f"{value:[fill][align][width][,][.precision][type]}"

align meaning group meaning
< left (default for text) , 1,234,567.89
> right (default for numbers) _ 1_234_567.89
^ centre
= pad between the sign and the digits

The fill character goes before the alignment character: {x:.^8} pads with dots.

%-style has left-align (%-10s) and right-align (the default) — but ^, =, a chosen fill character and , grouping are f-string only.

In [8]:
# alignment, fill, and grouping in one place
print(f"[{'hi':<8}]  < left")
print(f"[{'hi':>8}]  > right")
print(f"[{'hi':^8}]  ^ centre")
print(f"[{'hi':.^8}]  fill '.', centred")
print(f"[{-42:=8d}]  = pad after the sign")

[hi      ]  < left
[      hi]  > right
[   hi   ]  ^ centre
[...hi...]  fill '.', centred
[-     42]  = pad after the sign
